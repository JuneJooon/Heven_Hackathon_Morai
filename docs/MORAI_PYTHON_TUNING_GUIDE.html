실제 값이 선택되는 순서

  1. .py에 기본값이 선언됩니다.
  2. config/bringup.yaml에 같은 이름이 있으면 YAML 값이 기본값을 덮어씁니다.
  3. target_speed:=... launch 인자를 주면 그 값이 YAML의 target_speed까지 덮어씁니다.
예: control.py에서 kp=0.8로 바꿔도 YAML에 kp: 0.5가 있으면 실행값은 0.5입니다. Python과 YAML을 함께 맞추세요.

2. control.py — 가장 많이 조정하는 제어값

src/hk_morai/hk_morai/control.py · 상단 TARGET_SPEED_DEFAULT, PARAMS

값현재값높이면낮추면 / 언제 조정?
target_speed8.0 m/s
28.8 km/h		직선 목표속도가 증가. 곡률·법정속도 상한은 유지첫 주행은 6.0 권장. 차선 유지와 감속을 확인한 뒤 단계적으로 올림

planning_decel1.5 m/s²강한 감속이 가능하다고 가정하여 감속 시작이 늦어짐감속이 늦으면 1.2 정도로 낮춰 더 일찍 감속
speed_margin0.5 m/s제한속도 아래 여유가 커짐. 제한구간 목표속도 감소낮추면 제한속도에 가까워지지만 과속 위험 증가
zone_buffer5.0 m보호구역 제한을 더 일찍 적용하고 더 늦게 해제구간 경계가 정확하고 시간 단축이 필요할 때만 축소
launch_accel1.0 m/s²출발과 커브 후 목표속도 회복이 빨라짐출발이 급하거나 속도 초과가 생기면 0.7 정도로 낮춤
k_stanley1.0경로 옆 오차를 더 적극적으로 보정. 과하면 좌우 진동좌우 진동 시 0.8. 경로 복귀가 약하면 1.2를 시험
k_soft1.0 m/s특히 저속에서 옆 오차에 의한 조향이 약해짐낮추면 경로 복귀가 강해지지만 저속 조향이 민감해짐
steer_rate1.0 rad/s조향 명령이 더 빨리 바뀜. 급커브 반응 향상, 흔들림 가능조향이 급하면 0.8. 커브 대응이 늦으면 1.2를 시험
kp0.5속도 오차에 대한 가감속 반응 증가. 과하면 진동·초과반응이 너무 느리면 0.6, 속도 진동이면 0.4를 시험
ki0.05지속되는 속도 부족 보정 강화. 과하면 오버슈트속도 초과가 오래 이어지면 0.02 정도로 낮춤
brake_gain0.6같은 속도 초과에서 브레이크 명령 증가제동이 너무 거칠면 낮춤. 감속 목표는 내려갔는데 제동이 약하면 0.8 시험
brake_on_error0.3 m/s작은 초과속력에 덜 민감해짐이 값을 초과하면 제동 시작. 높이면 과속 여유가 줄어듦
brake_off_error0.1 m/s제동 해제가 빨라짐이 값 이하로 줄면 제동 해제. 0 이상, 시작 기준보다 작게 설정
input_timeout0.5 s오래된 odom/path를 더 오래 허용낮추면 빠르게 정지하지만 일시 지연에도 멈출 수 있음
헷갈리기 쉬운 차이
planning_decel은 “몇 m 전부터 목표속도를 낮출지” 정합니다. 실제 브레이크 명령 세기는 brake_kp × brake_gain이 정합니다. brake_kp 기본값은 0.5이며 가속 kp와 독립적입니다. 제동 중에는 초과속력에서 해제 기준 0.1m/s를 빼 적용합니다.

작은 속도 초과에는 구동을 끊고 타력 주행합니다. 입력 단절 뒤에는 현재 속력에서 목표속도 램프를 재개합니다. 노드 시작 시 적용된 목표속도를 출력하며, MORAI hold: 로그는 입력 단절·빈 경로 등의 정지 사유를 표시합니다. MORAI tracking: 로그는 2초마다 추정속력·목표속력·구동·제동 명령을 표시합니다.

5. speed_profile.py — 곡률 계산 범위

src/hk_morai/hk_morai/speed_profile.py · points[i-5], points[i+5]

코드현재 동작변경 효과
i-5, i+50.5m 간격 경로에서 전후 약 2.5m씩 보고 곡률 계산현재 기준
i-3, i+3더 짧은 구간의 굴곡을 봄급한 변화에 민감하지만 경로 좌표의 작은 흔들림에도 감속 가능
i-8, i+8더 넓은 구간을 평균적으로 봄부드럽지만 짧은 급커브를 완만하게 평가할 수 있음

함수 선언의 cruise=8.0, lateral=1.8, decel=1.5는 fallback 기본값입니다. 실제 실행에서는 control.py가 값을 인자로 전달하므로, 이 숫자만 수정해도 실행값은 바뀌지 않습니다.

곡률 감속 공식
커브 허용속도 = √(lateral_accel ÷ 곡률)
사전 감속 상한 = √(다음점 속도² + 2 × planning_decel × 점 사이 거리)

6. 증상별 빠른 조정표

주행 증상먼저 바꿀 값시험 방향다음 확인
직선에서도 좌우로 흔들림k_stanley1.0 → 0.8k_soft 1.0 → 1.5 또는 steer_rate 감소
경로를 벗어난 뒤 복귀가 느림k_stanley1.0 → 1.2k_soft가 너무 큰지 확인
커브 바깥으로 밀림lateral_accel1.8 → 1.5조향 변화율이 너무 낮은지 확인
커브 진입 감속이 늦음planning_decel1.5 → 1.2brake_gain과 실제 속력 추정 확인
목표는 내려가지만 차가 안 줄어듦brake_gain0.6 → 0.8speed_alpha 때문에 과속 인지가 늦는지 확인
출발 때 속도 초과·급가속launch_accel1.0 → 0.7kp, ki 순으로 확인
속력이 목표 위아래로 반복 진동kp0.5 → 0.4ki 0.05 → 0.02
GPS 위치와 조향이 흔들림position_alpha0.35 → 0.25IMU yaw 노이즈는 별도 필터가 없음을 고려
추정 속력이 흔들림speed_alpha0.5 → 0.25speed_window 0.3 → 0.5도 별도 검증. 추정 지연 증가 확인
보호구역에서 실제 과속speed_margin0.5 → 0.8zone_buffer와 제동 시작 시점 확인
아무 이유 없이 전제동input_timeout값부터 올리지 말고 odom/path timestamp와 발행주기 확인실제 일시 지연일 때만 소폭 증가

현장 튜닝 순서

  1. target_speed:=6.0 정도에서 위치·yaw·속력과 조향 방향을 확인합니다.
  2. 직선 조향을 k_stanley, k_soft, steer_rate 순서로 맞춥니다.
  3. 커브 속도를 lateral_accel로 맞추고, 감속 시점을 planning_decel로 맞춥니다.
  4. 실제 감속 세기를 brake_gain으로 맞춥니다.
  5. 속도 응답을 kp, ki로 맞춥니다.
  6. GPS 노이즈가 문제일 때만 위치·속력 alpha를 조정합니다.
  7. 한 번에 한 값만 바꾸고, 차선 침범·최대 속력·CP 통과·완주시간을 기록합니다.
첫 주행에서 바로 8m/s를 고집하지 마세요. MORAI는 공식 1회이고 차선 침범·과속에 큰 패널티가 있습니다. 6m/s에서 안정성을 확인한 뒤 올리는 편이 기록에도 유리합니다.

7. 적용 체크리스트

  1. Python의 알고리즘·상수를 바꿨는지, 파라미터 기본값을 바꿨는지 구분합니다.
  2. PARAMS나 localization 기본값을 바꿨다면 config/bringup.yaml의 같은 이름도 맞춥니다.
  3. target_speed는 실행 인자로 지정한 값이 최종 적용값입니다.
  4. 실행 중인 노드를 종료합니다.
  5. 다음 세 명령을 실행합니다.
colcon build
source install/setup.bash
ros2 launch hk_morai bringup.launch.py target_speed:=6.0 rviz:=true
